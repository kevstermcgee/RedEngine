# Writing a story for a Red game

A story is **text you write** (`.story` files), **compiled by a content build** (`red_engine2 story build`, milliseconds, no Rust) into a
package the game loads, and **run by the engine's story system inside the game's own authority**: it reads the game through typed queries,
changes it only through the game's commands, and its state is saved, checksummed, replayed and inspected with the game's. The decision record
is ADR 2026-10-15-narrative-is-compiled-content-run-by-one-story-system; the reference game is `games/tidewatch`; three small annotated
exemplars are in `examples/story/`. `red_engine2 describe story` is the one-screen summary of this page.

| command | what it does |
|---|---|
| `story check DIR` | parse, bind to the game, type-check, lint: every problem as `file:line: error\|warning[code]: message -> fix` |
| `story build DIR [--check]` | `check`, then write `DIR/<story>.story.json` (`--check`: fail if it is stale) |
| `story refs DIR ID` | who reads/writes/tells/jumps to `ID`; what a choice changes; why a conversation may be closed; what breaks if a line goes; where the scene's `checks.sim` and the folder's walks name it |
| `story ledger DIR` | setups and payoffs, each choice's stakes (declared and traced), facts' writers and readers, who can know what |
| `story review DIR` | the editorial sheet: characters side by side, choices, setups, and the questions only a reader can answer |
| `<game>_server cli story walk SCENE WALKS` | the real story under the game's real match, every choice at `*` steps explored, within bounds |
| `<game>_server cli sim SCENE --inspect story` | a scenario's run, then the story's state and its decision log (why each line was said or not) |

## The workflow (do it in this order)

1. **Inventory** what the game really has: `story bindings` (`bindings.json`, generated by the game) lists every query (what a condition can
   read), command (what an effect can do; `unattended` ones a director may) and event (what a bark answers); the scene's `vars` are
   `scene:<name>`; walk the map (`plan`, `tour`) for its places. Nothing else exists.
2. **Premise**, grounded in that inventory: what the player does, where, under what pressure. One paragraph. If it needs a verb the game lacks,
   write `request <id> "<what the game would need>"`: every check lists it until the game offers it. Never invent a mechanic in prose.
3. **Character sheets** (below): want, need, flaw, contradiction, values, relationships, voice and two original example lines each.
4. **Choose a structure** that fits the game, not a formula: a recipe below, or your own. Short games want short arcs.
5. **Skeleton and bindings**: conversations and nodes with `->` only, barks with their events and conditions, facts and infos. `story check`
   until it is clean: names, types and flow are right before a word of dialogue is polished.
6. **Scene by scene dialogue**, one node at a time, in each character's voice.
7. **`story build`**, then **scenarios** (`checks.sim` story steps) for the paths that matter, and **`story walk`** for the branches.
8. **Editorial review** (`story review`): answer its questions with line ids.
9. **Patch only what the review or a check names.** Never regenerate a whole story to repair a local problem: `story refs` says what a change
   touches.
10. **Play it natively** (the game's own client), then a person plays it.

## The format

Line-oriented, indentation-free (indent for readability): a keyword opens an item; an attribute line belongs to **the nearest item above
it**. `//` starts a comment line. Ids are lowercase letters, digits and `_`, unique in the story.

```
story <name> version <n>        every file says `story <name>`; one says the version (raise it when saves of old content should be read by id)
uses <bindings.json>            the game's bindings (relative to this file)
map <scene.json>                its scene: `vars` become `scene:<var>` (true/false start = yes/no, whole number = int)
round <event>                   round facts and director budgets reset when it happens
style max_line <n>              the long-line warning's limit (default 200)

character <id> "<Name>"         a major character: the sheet fields below, each `field: text`
extra <id> "<Name>"             a minor speaker: `role:` and `voice:` (plus optional fields)
fact <id> bool|int = <v> [round|run|profile] [shown] "<what it means>"     story-only state (never gameplay: that is a query)
info <id> "<what it says>"      something that can be known;  `true if <expr>`: when it is true in the world
setup <id> "<what was established or promised>"
  by <line or choice>           where it is established
  pays acknowledge|resolve|complicate|leave <line, choice or bark>
category <id> cooldown <secs>s  barks of a category share a cooldown
request <id> "<what>"           a mechanic the story wants and the game lacks (listed by every check)
allow <warning> <id> "<why>"    accept one warning about one thing, with its reason (listed by every check)

conversation <id> with <speaker>    opened by talking to that speaker (when they are present)
  if <expr>                     when it may open        priority <n>   several may: highest first
  interrupt <n>                 a bark of this priority or more suspends it (it resumes after)
  repeat                        it may open again after it ended
node <id>
  <speaker>: <text>             a line; `narrator: ...` has no speaker; `{name}` shows a number (an int fact or query)
    if <expr>                   said only when it holds, else passed over (on to the next line; a node's last goes where it would)
    do <effect>; <effect>       applied when the player moves past it (commands first, as one batch)
    reveals <info>              the speaker tells it as true (they must be able to know it); listeners know it
    claims <info>               the speaker asserts it without knowing (speculation, a lie): listeners only believe it
    id <name>                   its id (`<conversation>/<name>`; default `<conversation>/<node>/l<n>`)
    -> <node>|end               where it goes when said (a node's last line must say)
  * <choice>: <text>            a choice of the line above (that line must end its node)
    if <expr>                   offered only when it holds; checked again when picked
    do <effect>; ...            applied when picked, after the line's own
    kind consequential|informational|expressive    what it is for (checked against what it changes)
    -> <node>|end               where it goes (required)
    else -> <node>|end          where it goes when the game refuses its commands
  otherwise -> <node>|end       (on the choice line) where it goes when no choice is offered

bark <id> on <event> [about <subject>]    a contextual line answering a game event
  <speaker>: <text>  |  silence           its line, or a deliberate nothing
  if <expr>   priority <n>   cooldown <secs>s   once   category <id>   do ...   reveals ...   claims ...
bark <id>                       one only an effect or a director offers
notice <id> on <event>          never speaks, never competes: when the event happens and `if` holds, `do` applies (witnesses `learn present`)

director <id>
  every <secs>s   recover <secs>s   budget <n> per round   tension <expr>   rest if <expr>
  intervene <id>
    if <expr>   chance <n>%   group <id>   once   do <effect>   (commands only the game's `unattended` ones)
```

**Effects:** `set <fact> = <expr>`, `add <fact> <expr>`, `learn <who> <info>`, `believe <who> <info>` (who: `player`, a character,
`present`, `everyone`), `run <command> [on <id>] [<value>]`, `bark <id>`, `start <conversation>`.

**Expressions** are the rules' language (`describe rules`): numbers, `true`/`false`, `+ - * / %`, comparisons, `&& || !`, `floor round abs
sqrt min max`, plus names: a fact (`lent_fuel`), a query (`tw:shed_fuel`, `scene:near_bram`), `knows(<who>, <info>)`, `believes(<who>,
<info>)`, `heard(<line id>)`, `present(<speaker>)`. Each is lowered to a variable lookup; nothing calls into the game. A condition must be a
yes/no; an int fact takes a whole number; a yes/no counts as 0 or 1 in a sum. `random` is refused (a condition must not draw).

**Refused, by name:** Ink knots, tunnels, `VAR`, `~` logic, `INCLUDE`, Yarn `<<commands>>` and `---`. This is not Ink or Yarn.

## How it runs (the contract)

- **One authority.** The story is a game system (`<story>:story`) in the game's host: no second simulation. It reads only declared queries,
  and it acts only through declared commands, as one batch per decision, whole or not at all.
- **Answers name a revision.** A client shows the story's `View` (its `revision`, the line, the choices offered now) and sends intentions
  (`story:talk`, `advance`, `choose`, `leave`, `skip`) naming that revision. A stale or repeated answer is refused. A choice is checked again
  against live state when picked. Its commands apply first; if the game refuses one, nothing of the choice applies and its `else` (if any)
  takes over.
- **Conversations.** A conversation line is *heard* when the player moves past it (its effects and reveals apply then). A line whose
  condition is false, whose speaker is away, or whose speaker does not know what it reveals is passed over without effect. The world does
  not pause: a game may hold the player still while one is open (Tidewatch does).
- **Barks.** On an event every `notice` that holds applies. Then the barks choose: candidates are checked by pure conditions (nothing is
  marked, drawn or started by checking; one already playing or queued is held back). The best is chosen by highest priority, then most
  specific (the parts of its `if`, and an `about`), then least heard, then first written. A real tie draws once from the host's seeded
  stream, when one is committed. Choosing starts three cooldowns: the bark's own, its category's, and its speaker's. The speaker's holds
  back only their lines of no higher priority, so chatter never silences an alarm.
- **Presentation and queueing.** A bark plays for 1.5 s plus 0.067 s a character (at most 7 s). It is *heard* when that time is up or the
  player skips it, and its effects and reveals apply only then. A higher priority interrupts it (then it was seen, not heard, and may play
  again). A conversation is suspended only by a bark of at least its `interrupt` priority. Others queue: three at most, each stale after
  4 s and checked again before it plays. With no candidate, the outcome is silence, logged with each candidate's reason.
- **Directors.** Each evaluates `every` so often, never while a conversation is open, never inside `recover`, within `budget` and `group`s.
  `rest if` makes it do nothing on purpose; `chance` draws once, only for an otherwise eligible intervention. When every intervention is used
  up it reports `exhausted`: variety is finite, and the log says so. `tension` is a game-defined pacing number, not a feeling.
- **Knowledge.** Each holder (the player, each character) knows or believes each info, with where it came from: their sheet, a line heard,
  an effect. A reveal of something untrue is only believed. Nobody learns what they were not present for, unless an effect says so.
- **Facts.** Facts with `round` scope reset on the round event. `story:new_run` resets everything but `profile` facts. The game may read any
  fact as `<story>:<fact>`.
- **Saves** are by id (facts, lines, barks, conversations, knowledge): a newer content version or another story is refused; an older one
  loads, reporting what no longer exists.

## Lint

**Errors** (nothing is built): syntax and refused foreign syntax; unknown names (with a did-you-mean); types; bindings the game does not
declare; a director running a command the game does not allow unattended; a speaker revealing what they could never know; a missing
profile field; a node without lines, or one ending without `->`; a choice without `->`; a conversation that can never end; lines that can all
be passed over in a loop (a loop that never waits for the player).

**Warnings**, each about one thing and each acceptable with `allow <warning> <id> "<why>"`:

| warning | means |
|---|---|
| `unread` | a fact is written, but nothing reads it: no condition, no text, not the game, not `shown` |
| `unwritten` | a fact is read but never changes |
| `unused` | a fact or info nothing uses |
| `untold` | a condition asks who knows an info nobody can ever learn |
| `unpaid` | a setup that nothing acknowledges, resolves or complicates, and nobody leaves on purpose |
| `stakes` | a choice's declared kind is not what it changes |
| `equivalent` | two choices that do the same thing and go to the same place |
| `repeat` | the same words twice, or one bark answering an event every time |
| `fallback` | when no condition holds, nothing is offered or said (a deliberate `silence` says it is meant) |
| `unreached` | a node nothing leads to |
| `length` | a line longer than `style max_line` |
| `else` | an `else` that can never be taken |
| `request` | an open implementation request |

**Stakes** are traced from what a choice actually changes. A choice that runs a command, or changes a fact or a knowledge that something
reads, is *consequential*. One that tells the player something is *informational*. Anything else is *expressive*: a difference of voice,
which is fine. A written variable is not, by itself, a consequence.

**Not linted: the writing.** A generic premise, a flat motivation, interchangeable voices, needless exposition, an unearned reversal, or a
consequence no player can perceive: these are for `story review` and a reader. No check bans emotion words, long lines, stable
characters, endings or branches that converge.

## Character sheets

A major character (`character`) needs `want:` (what they are after now), `need:` (the tension under it, or `arc: stable, <why they do not
change>`), `flaw:`, `contradiction:`, `values:` (and `boundaries:`), `relationships:`, `voice:` and two or more `example:` lines of their own.
An extra needs `role:` and `voice:`. The machine reads only `knows:` (infos they know when the run begins), `present:` (a yes/no query or scene
variable: are they here) and `cooldown:` (seconds between their barks). `beliefs:` and `secret:` are for you. A missing field is an error; a
bland one is not detected: that is the review's job.

## Craft

- **Motivation and causality before polish.** Know why each character speaks now: what they want from this player, this minute.
- **Consequences through play.** A choice should show up in the world (a lamp lit, a door shut) or in what someone later says or does.
  `story ledger` shows the trace of each choice.
- **Voice from perspective.** Two characters reacting to the same event should disagree about what it means. Do not give them catchphrases.
  Test it: cover the names; can you still tell who is speaking?
- **Subtext where it serves; direct speech where it matters.** People dodge, deflect and joke. But a key fact, said plainly at the right
  moment, lands harder.
- **Let the place and silence speak.** A narrator line about the square, an empty dock, a `silence` bark: often enough.
- **Callbacks name what this player did** (`if lent_fuel`, `heard(...)`), not a generic "you".
- **Pace for the game.** Short barks in action. Conversations where the world allows them. Not every event deserves a line.
- **Refusal, delay and failure are answers.** Give each its own reply and its own aftermath, a watch later if need be.

## Optional recipes

- **Escalating complication:** a want, an obstacle the game can produce (a query going bad), and a second, worse obstacle. Each step is a
  bark on the event that causes it. A director may offer help but never adds the obstacle.
- **Revelation:** an info someone knows (`knows:`) and reveals only when asked (`reveals`). Another character believes something else
  (`claims`). A later line differs by who knows what (`knows(odile, ...)`).
- **Relationship / commitment:** a promise is a fact plus a setup. It is resolved by keeping it, complicated by breaking it, and
  acknowledged by a bark when its time comes (`examples/story/the_debt`).
- **Systemic aftermath:** barks on the game's own events, noticed by whoever is present (`notice`). A director that rests when things are
  tense. No conversation is needed (`examples/story/rain`).

## Exemplars (`examples/story/`, each annotated, each compiled by a test)

- `the_debt` (warm, wry): a baker, credit and a promise kept or broken by evening. Commitment, refusal, a callback by the clock.
- `the_rumour` (tense): a claim that is false, a miller who reacts only if he knows you heard it. Claims versus knowledge, a withheld line, a
  `notice`, silence as an answer.
- `rain` (quiet): weather barks, deliberate silences, a director with a chance that gives up after its budget. Story with no conversation.

Tidewatch (`games/tidewatch/content/story`) is the full-size reference: two voices, a decision that moves real peat, a delayed callback, a
promise, knowledge that gates lines, an interruption, a director over live state.

## Proving it (and what each level claims)

- **Content-valid:** `story check` / `validate` clean.
- **Behaviourally verified on tested paths:** scenarios with story steps in `checks.sim` (`{"player": "p1", "story": "talk", "to": "bram"}`,
  `"advance"`, `"until_choice"`, `{"story": "choose", "choice": "lend"}`, `"leave"`, `"skip"`, `"revision": n` for a stale answer), with
  expectations on the story's state: `{"game": "story", "path": "<path>", "eq|ne|gt|gte|lt|lte": <n>}` (`eq`/`ne` also take text). Paths
  into `sim --inspect story --json`: `facts.<fact>`, `heard.<line id>` (ids with `/` are fine), `chosen.<bark>`, `reads.<query>` (the live
  value of every query the story reads, `reads.tw:shed_fuel`), `revision`, `round`, `view.talk.line.id`, `view.bark.id`, `ended.<n>`; and
  `{"game": "<story>:<id>", "path": "status", "eq": "blocked"}` for a conversation, bark, director, fact, info or speaker (`sim --inspect
  <story>:<id>` prints what it has). Also `story walk` over the `*` choices: it is exhaustive only over those
  choices, from that start and script, and only when it says so.
- **Native presentation inspected:** the game's client, rendered offscreen (`games/tidewatch/out/*.png`) and looked at.
- **Editorially reviewed:** a reader answers `story review`'s questions.
- **Human-playtested:** a person played it. Nothing above certifies that the writing is good, or fun: that takes a blind comparison by people.

## Binding a story into a game (for game authors)

A game crate composes `sim::story::runtime::Story` into its `Systems` beside its own systems. It loads the package with
`Loaded::from_json(text, &Catalog::of(&[&its systems], scene_vars))`, which runs the same check and bind the toolchain ran. It ticks the host
with `tick_with(sim.rules())`, so `scene:` reads are answered. Its `MatchGame::intend` passes intentions to `story::intend`, its `inspect`
answers through `story::inspect`, and its `input_locked` may follow `Story::locks_input`. Its systems declare `queries` (typed, pure),
`commands` (the `unattended` ones a director may issue) and `emits`. Its program prints the bindings file (`story-bindings`); a test keeps
that file and the package fresh. `games/tidewatch/server` is the whole pattern (about 700 lines with its gameplay). The presenter `app::dialogue::Presenter` is
optional.

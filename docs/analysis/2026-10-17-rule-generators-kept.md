actions ... all generated by a Python script outside the repo", F2). The script was then lost, so the next change to the game meant editing generated JSON by hand.

## The change

- **The brief** (2D and 3D) says: a script that writes rules, levels or objects is `examples/<kind>/<slug>/build.py`, with any helpers beside it. Write it
  there from the start, never in /tmp, and commit it with the game (`examples/2d/honeybound/` is the pattern). Standard library only, paths relative to
  itself, and running it again rewrites the game byte for byte. Change the game by editing the script.
- **`ship`'s allowed paths:** a 2D game may also change `examples/2d/<slug>/` (3D games already owned their folder), and `ship` commits it. `settle`
  re-checks GitHub's file list with the same rule.
- **`scripts/game_generators.py check`:** finds `build.py` (or `gen.py`) in every game folder and runs it in a temporary copy of the folder, with the game
  file removed so that a generator that writes nothing fails, and `PYTHONHASHSEED=0`. It compares every file with the committed one: a different byte
  (with the line), a file it did not write, a file it writes that nobody committed, a crash, a 120 s timeout. It runs in three places: the run's score
  ("its generator rewrites the game byte for byte"), `feedback --check` (so the agent fixes it during its run), and CI's `content` job, which runs for
  every pull request that changes engine files or games (`native` or `games_only`).
- **Measurement for the future:** each feedback file's automatic block now lists "Python scripts written outside the game's folder". The next nightly
  runs show whether agents follow the brief, with no manual scan.

## CI: a games-only pull request stays on the fast path

`ci.yml`'s `pytools` output was true for any `*.py` (ADR 2026-10-09-ci-runs-the-python-tools-on-windows-when-they-change, now amended), so a game PR with its
generator would start the `python-tools` job on Linux and Windows. Measured on the last 8 successful runs of that job: Linux mean 71 s, Windows mean 174 s,
about 4 job-minutes per game PR (Windows minutes bill double). A `*.py` under `examples/2d/` or `examples/3d/` no longer sets `pytools`.
`scripts/test_ci_selection.py` runs the workflow's own step and proves it:

| changed files | before | after |
|---|---|---|
| `examples/3d/x/build.py`, `examples/3d/x/x.json` | games_only, **pytools** | games_only |
| `examples/2d/x/build.py`, `examples/2d/x/levels.py`, `examples/2d/x.game2d.json` | games_only, **pytools** | games_only |
| `examples/3d/x/build.py`, `scripts/idea_forge.py` | pytools | pytools (a tool changed) |
| `examples/external/tool/helper.py` | pytools | pytools |

The generator check adds about 0.2 s to the `content` job (two generators today).

## Not done

  its JSON.

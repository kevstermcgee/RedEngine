## The game

**Mechanic:** you tune a radio whose frequency opens one colour of gate (wood, tin, brass) but you can never pass the same colour twice in a row. Every room is a row of gate columns with two lanes of different colours; the core loop (every few seconds) is to pick a lane, turn the dial to its colour, walk through, and plan the next colour so it differs. Each dial turn is a jolt (+7 panic) and a repeated colour is a shock (+55); panic bleeds off slowly and each cleared room soothes it by 25. Panic 100 wakes the friend and loses; the tenth door wins ('dawn'). Best room reached is saved. The lighthouse-keeper story is only a hint text and a title.
**Adapted:** 'every frequency rewrites one rule' became 'every frequency opens one surface colour' (the dial rewrites which gates are solid), and 'sudden moves' became dial turns because rules cannot read acceleration. Cut: separate rule changes per frequency such as friction or gravity, which the 2D format cannot change at runtime. The idea fits, but it is a gate puzzle more than an action game; the top-down walking is deliberately plain.

## Idea fit

YOU (dial rewrites the room) and BUT (never touch the same surface twice) are expressible: `become` by tag flips gates and `touch` rules track `last`. Not expressible: per-frequency changes to movement physics (no runtime change of a mover's speed or friction except by `become` on the player), a jerk/sudden-move sensor, and an if inside do lists. Everything else was data.

## What worked

The prebuilt fetch (no compile), `describe 2d`, validate messages with did-you-mean, `sim --every`, `frame` PNGs, and 21 checks in under a second. Effects, ui buttons with keys, `persist` and the save round trip check all worked first time.

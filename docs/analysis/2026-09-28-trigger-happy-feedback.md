# What building Trigger Happy taught us about Red (2026-09-28)

An AI built **Trigger Happy**, a first-person Gun Game arena shooter with bots, on Red and wrote down what worked, what cost it time, and what it would build next. The game shipped with one real bug: bots in bodies other than the human's were invisible, because nothing could look at the game or ask the client what it drew. This note evaluates that feedback, what changed in Red because of it, what changed in the game itself (the engine work behind Trigger Happy — ADRs 0050-0057 — was already on `game/work`), and what is still open. Two more things were done in the same pass at the user's request: the silver revolver (the one weapon that was not a data row like the others) was removed from the engine, and native save states were requested — see "Not in this pass" below for its real status.

## The short version

* The invisible-bots bug shipped because the real client could not be tested or looked at without a window, and every silent skip ("no avatar for this body, draw nothing") had no counter. Items 1-3 fix exactly that: a headless client, offscreen capture, a scripted player, a state dump, and a counter for every way a remote player can fail to be drawn.
* `tests/client_headless.rs` reproduces the original bug directly — a real hosted server plus the real client, four humans forced to one body and a four-bot roster in four other bodies — and shows it is fixed: all 7 non-self players drawn, 0 undrawn. `red_engine2 playtest maps/arena.json --fill 8` on Trigger Happy's actual arena with its actual roster confirms the same thing outside a test harness.
* A fast `preflight` (item 5) and a documented `[profile.fast]` build profile (part of item 6) are also in.
* Several other items from the feedback (a human-proxy tuning tool, a sound-lab, a nav-graph generator, a packaging/prebuilt-kit command, a map-declared options screen, native save states) were started on separate branches during this pass but are **not yet merged into `game/work`** — see "Not in this pass".

## The feedback, item by item

| # | The feedback | Status | What now happens |
|---|---|---|---|
| 1 | Couldn't see the game the way a player does; nine one-off PowerShell capture scripts; concurrent runs photographed each other | **done** (ADR 2026-09-28-seeing-what-the-player-sees) | `re2 --shot-at 5,10 --shot-dir out/`, F12, and a script's `shot` step render the frame a second time into an offscreen target and read it back — no focus, no visible desktop, nothing to photograph by accident. `red_engine2 playtest MAP --secs 60 --shots 12` hosts a match, plays a scripted player (spin, walk, aim, fire, overview and follow cameras) and writes the pictures, a labelled contact sheet and a JSON report. A server-side spectator seat was not built; the overview/follow cameras are client-side. |
| 2 | The real client can't be tested headlessly; the glue that decides who gets a body had no test | **done** | `re2 --headless --script play.json --dump state.json` steps the same `App` the window steps, with a null renderer (a GPU is only needed if the script takes a picture). The dump (`re2-dump/1`) lists remote players and their avatars, the HUD text, cues, the crosshair and every counter; script `expect` steps assert on it by JSON pointer. `tests/client_headless.rs` runs the real binaries end to end. |
| 3 | Silent failures cost a debugging round each (skipped avatars, players vanishing with no portals, a slab shoving a jumper sideways) | **done** | Every failed lookup counts (`RemoteStats`/`SessionCounters`: undrawn, stand-in, unposed, hidden by interest, pool use) in `RE2_STATS`, the F3 overlay and the dump, plus a warning the first time a player can't be drawn. New lint rules: `interest` (a map's occupied rooms with no portal path between them — see the caveat below) and `jump-clearance` (computed from the map's own `player` tuning). `game check` verifies every roster body has an avatar. Caveat found rolling this out: the lint compares *all* of a map's spawn points, not per spawn `group`, so a shared reference/testbed map with several unrelated spawn groups (like the engine's own Test Lab) can get a warning that isn't actionable; grouping the check by spawn `group` is the cleaner fix and is not done yet. |
| 4 | Pre-allocated pools are the only way to add dynamic things; hidden objects still cost draws | **done** | `ScenePool` owns sizing, claiming and hiding of pooled scene objects (avatars, tracers, sparks) in one tested place; `LiveRenderer::set_hidden_objects` skips hidden objects instead of drawing them at scale 0.0005. General mesh add/remove after renderer creation was not built. |
| 5 | CI bookkeeping fails after the work is done (an ADR in four places, file ownership, a byte budget, protocol bumps by hand, ADR number collisions across branches) | **done** (ADR 2026-09-28-generated-bookkeeping) | `red_engine2 preflight [--fix]` (about a second, compiles nothing) checks and repairs it; ADR files are the registry (the README index is generated); dated ADR ids (`adr new "title"`) avoid cross-branch collisions; file ownership and the protocol version in the docs are derived facts. |
| 6 | Build cost (4-minute LTO builds, a stale `red_engine2` after `cargo build --bin re2`, a `rustc` crash at codegen-units=16, C: filling up) | **partly done** | `[profile.fast]` is checked in and documented. A prebuilt engine kit and honouring `CARGO_TARGET_DIR` everywhere were started on the `agent/game-package` branch, not yet merged (see below). |
| 7 | Windows shipping (a stale console handle blocked `println!` forever; packaging written from scratch; difficulty `.cmd` launchers because there's no options screen) | **partly done** (ADR 2026-09-28-windows-shipping) | `re2` now sets up its output for how it was started (terminal, double-click, redirected), logs to `re2.log`, and shows a crash box on a panic; `tools::pe` can flip a built exe to the GUI subsystem so a shipped copy never opens a console. `red_engine2 package`/a prebuilt kit and a map-declared `options` screen were started (`agent/game-package`, `agent/options`), not yet merged. A Windows CI test that closes the window and expects a clean exit was not built. |
| 8 | Tuning fun needs a human proxy (bots vs bots only) | **started, not merged** | `agent/bot-match` has a `red_engine2 bot-match --json` command with health thresholds and a human-proxy profile; not yet reviewed or merged. |
| 9 | Audio is blind for an AI | **started, not merged** | `agent/sound-lab` has a `red_engine2 sound-lab` command rendering cues to WAV plus waveform/spectrogram images and stats; not yet reviewed or merged. |
| 10 | More data-driven blocks so games need no engine edits (hud, sfx/music palettes, pickups, teams, kill feed) | **not done** | The engine work behind Trigger Happy (bots, ladder, pacing, feedback, feel, lag compensation, client hosting, tracers, music, avatars) is already on `game/work`. The newer blocks need protocol and UI design (a kill feed needs the killer's id on the wire; teams change scoring and spawns) that a second game should drive. |
| 11 | Orientation cost, undiscoverable debug switches, `player.character` reads as global | **done** | `docs/LIFE_OF_A_SHOT.md` and `docs/LIFE_OF_A_REMOTE_PLAYER.md` walk one trigger pull and one remote player through the code (function, tuning key, how to see it, its classic silent failure). `re2 --debug-help` lists every `RE2_*` switch and hotkey (a test keeps it complete). `player.humans_play_as` is the clear name (`player.character` still works). |
| small | Net tests use real-time UDP; no in-memory transport with a virtual clock | **not done** | It is a refactor of every socket use in the server and client. |

## Also done in this pass (not from the feedback)

* **The silver revolver is gone** (ADR 2026-09-28-remove-the-revolver, requested directly): it was the one weapon with its own model, constants and scene key instead of being a `FirearmSpec` row like the other ten. `weapons.ammo` replaces `weapons.revolver.ammo` as one setting shared by every firearm. Removing an entry from the wire's weapon list bumped the protocol to v9. Trigger Happy's ladder is now ten firearms and the bat (11 rungs); its map, docs and scripts were updated to match but its own repository has not been committed yet.
* A `nav-build` command that generates a bot navigation graph from a map's own walkable-reach analysis, instead of hand-typed waypoints, was started on `agent/nav-build` — not from the feedback, not yet merged.

## Not in this pass

**Native save states**, requested directly by the user alongside this feedback pass, are **not done**. The design (a `.rstate` container, a transactional `MatchSim::capture`/`restore`, canonical bytes, proofs that a save-then-resume run is bit-identical to a continuous one, hostile-input fuzzing, CLI and server integration) is written down in the `agent/save-state` worktree's brief, and that branch has only enabled a Cargo feature flag (`rapier`'s `serde-serialize`) needed for the physics half of the state — essentially unstarted. This is real, correctness-sensitive work and rushing it would mean shipping something unproven; it is left for a dedicated follow-up rather than merged half-finished.

## What is verified, and what is not

* `cargo test --lib --bins`: 514 passed, 0 failed. `cargo test` (every integration suite, parallel and serial): passing after two lint-driven fixes to existing tests (`examples/test_lab.json`'s own lint budget, and a recipe-based test that needed a portal the new lint correctly asked for). `cargo clippy --all-targets -- -D warnings`: clean. The headless build (`--no-default-features`) and its own clippy/tests: run as part of the same CI pass.
* Trigger Happy itself was played, not just unit-tested: `red_engine2 game check` and a real `playtest` run against its actual arena map and 8-bot roster, contact sheet included.
* Not verified: the six side branches above (`agent/save-state`, `agent/options`, `agent/sound-lab`, `agent/bot-match`, `agent/nav-build`, `agent/game-package`) have not been code-reviewed, merged, or run through CI as a combined tree.

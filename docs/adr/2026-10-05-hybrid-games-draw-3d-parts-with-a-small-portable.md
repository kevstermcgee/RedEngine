# 2026-10-05. Hybrid games draw 3D parts with a small portable renderer, and distribution is a declared axis
Status: accepted
Summary: A 2D game may draw models, viewports, a perspective world and a minimap with a deterministic software 3D renderer inside red2d, so it keeps headless verification and browser play; online and install are checked together for every presentation.

## Context
The brief: the AI designing a game should pick 2D or 3D elements freely per game (a minimap over a 3D-looking game, a 3D boss in a 2D game), and every game should be publishable online and installable. The wgpu engine cannot run in a browser yet, so "3D" and "plays from a URL" were mutually exclusive, and a game that wanted one 3D thing had to become a whole 3D project (blueprint, server, installer) or give it up.

## Decision
A third presentation, `hybrid`, which is a 2D game (`*.game2d.json`, one simulation, one input model, one save) that draws some elements in 3D through `red2d::raster3d`, a small software renderer: flat or toon shading, one light, a depth buffer, primitives and voxelised sprites, billboards, `libm` trigonometry only so native and WebAssembly agree bit for bit. It is declared (`presentation: "hybrid"`) and checked: declaring it with no 3D element is an error, and using a 3D element in a `2d` game is an error that names the element. The 3D elements are `models`, a prefab `shape.model`, `view3d` (widget or `layers3d`), `view.world3d` (ground or wall plane; `height3d` makes boxes; pointer and clicks are unprojected) and `minimap` (valid in any game). A hybrid game is supported exactly where a 2D game is (`caps::portable`), so it is verified headless, compared pixel for pixel with the browser, published and installed (web app) like any 2D game. `propose` recommends it when an idea wants a 3D part and 3D when it wants a 3D world; `describe hybrid` is a separate topic so `describe 2d` stays small.
Distribution is its own declared axis (`online`, `install`) in the same capability matrix. Both are supported for 2D and hybrid (the package is a URL and an installable offline web app that keeps saves); 3D is install-only until the engine runs in a browser, and the matrix says so with the reason.

## Consequences
Easier: a game gets a 3D boss, a spinning HUD portrait, a world in perspective or a minimap in a few lines of JSON, and every check that exists for 2D still works. Harder: two renderers exist (this one is deliberately small and CPU-bound: a few thousand triangles at 320x180; no textures, shadows or big worlds), and the world view is a view of a flat simulation, not 3D physics. wgpu in the browser is not delivered by this and remains the route for real 3D online. To undo: drop `game3d.rs`/`raster3d.rs` and the render arms; games that never used the 3D keys are unaffected.

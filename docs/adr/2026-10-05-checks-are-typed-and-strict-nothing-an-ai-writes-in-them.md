# 2026-10-05. Checks are typed and strict: nothing an AI writes in them is ignored, defaulted or vacuous
Status: accepted
Summary: Every checks.* field is typed with an exact path, expected alternatives and a likely fix; groups and items that assert nothing are errors; checks.audio hears what the player hears; scenarios need expectations.

## Context
`verify` is how an AI learns whether its game works, so a check that is ignored is worse than one that fails. The `checks` block validated only some keys, and read every value with `as_f64().unwrap_or(default)`: `"peek_max": -3` did nothing, `"reachable": "false"` meant `true` (the opposite), `"max_warnings": "5"` set no limit, `"secs": 99999` was clamped silently, a `soundscape` item with no `calls` or `beds` passed with an empty detail, and a scenario with no `expect` proved only that nobody got stuck. The flagship example's own `checks.audio` failed `verify` (it ran the ambience without applying the scene's `audio.birds: false` and counted 190 calls nobody hears) and nothing noticed because no test ran it. Sweeping the shipped content found three published games with an empty `"walk": []` and one `walk.to` written with three numbers where the third was silently dropped.

## Decision
`strict::check_fields` takes a table of `Field { key, Ty, hint, required }` and reports, at the exact path, an unknown key (with `did you mean`), a value of the wrong type ("expected true or false, got string \"false\""), a number outside its range, a name that is not a lint code, call, bed or biome (with the alternatives), and a missing required key. `tools::check_schema` holds the tables for every group of `checks`, `tools::audio_checks::invalid_fields` the audio ones. A group or item that asserts nothing is an error that says so (`{}`, `[]`, an `objects` check with no assertion, a `count` with neither `min` nor `max`, a soundscape with no `calls` or `beds`, a walk with neither `path` nor `to`). `checks.audio.soundscape` runs the ambience as the scene's `audio` block configures it (an item may override `birds`). A `seam_max` on a one-shot is refused, since a one-shot never plays that join. `sim` scenarios need a non-empty `expect` and numeric `max_seconds` and `settle_seconds`. `tests/checks_wellformed.rs` holds every shipped scene to the same rule and runs Marcel's soundscape checks.

## Consequences
A plausible mistake is one message with its fix, never a green result. Games that pin an engine from before this change are unaffected; a project that updates will see its own vacuous checks fail (`storm-cell`, `domino-dynamo`, `skyhook-sprint` and `redengine-sandbox/workshop-motion-lab` in RedEngineGames do: they are listed in the milestone note and were not edited, since changing a map re-releases the game). Not covered: the *values* inside `perf` budgets beyond their existing typing, and whether a check is *meaningful* (a lint budget of 50 errors is well formed).
